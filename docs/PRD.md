# PRD — MetroFlow (Self-learning traffic for city builders)

## 1. 목표/배경
시티빌더(예: 시티즈 스카이라인 2급)에서 인구 ~10만 도시 규모를 대상으로,
(1) 개별 시민의 주소/직장/일정 기반 agent를 유지하면서도,
(2) “무조건 최단거리” 류의 경로 고착으로 인한 비현실을 완화하고,
(3) 외부 데이터 없이 시뮬레이터 경험으로 **점진적으로 더 현실적인 분포**로 진화하는
경량 교통 엔진/보조 알고리즘을 제공한다.

핵심은 “모든 agent가 완전 최적화된 내비를 들고 있다”가 아니라,
**부분 정보 + 습관 + 사회적 상호작용(Active matter) + 제한된 내비 업데이트**를 합성해
현실적 우회/분산/병목을 만든다는 점이다.

## 2. 사용자(플레이어) 스토리
- 플레이어는 “도시 구조(대로/고속도로/IC/다리/교차로) + 존(주거/상업/공업/도심)”을 설계한다.
- 시민은 개별 주소/직장/여가 장소를 갖고, 시간대·평일/주말에 따라 트립을 만든다.
- 교통은 혼잡/사고/공사 등 이벤트에 반응하며, 일부는 우회하고 일부는 고집한다.
- 시간이 지날수록 시민(정책 공유)이 경험으로 학습해서 “자주 막히는 길 회피”가 자연스럽게 생긴다.
- 플레이어는 “교통 혼잡 heatmap + 주요 corridor 흐름 + 평균 통근시간”을 UI로 본다.

## 3. 스코프
### In-scope (MVP~v1)
- 도시 생성(가상 도시 구조): 소로/대로/도시고속도로, 대교, IC, 주요 교차로
- 존/랜드유즈: 베드타운, 도심(CBD), 상업지구, 공업지구, 혼합지구
- 수요(인구 10만): 가구/직장 매칭 + 시간대/요일 기반 트립 생성
- 교통 엔진(메조): 링크 큐 + 노드 턴/신호의 단순화 모델
- 라우팅: (동적 퍼텐셜 기반) + (학습 policy) 혼합
- 학습: 외부 데이터 없이 online. “너무 강한 RL” 대신 안정적인 bandit/actor-critic 옵션
- 실시간 시각화: 네비게이터 스타일(지도+흐름+혼잡 레이어) + 시간대/주말 토글

### Out-of-scope (v2+)
- 완전한 미시 차량 추종 모델(IDM 등) 디폴트화
- 고정밀 실제 지도/행정구역 import
- 보행/대중교통/자전거 완전 통합(단, 확장 포인트는 설계)

## 4. 성공 지표
- 성능: 인구 100k, 동시 이동 10k~30k에서 “게임틱 0.1~0.5초” 수준으로 step 가능(타깃)
- 행동 다양성: 동일 OD에서도 경로 분산(엔트로피) 발생 + 병목 우회가 부분적으로 나타남
- 안정성: 정책 학습이 발산하지 않고(혼잡 무한 폭증), 수요/공급/보존 불변량 유지
- UX: 사용자가 “시간대별 병목이 왜 생기는지” 읽을 수 있는 UI 제공

## 5. 제약/리스크
- online 학습은 불안정해지기 쉽다 → **보수적 학습률/클리핑/안전 정책(최단경로 fallback)** 필수
- agent를 유지하되 계산량을 억제해야 함 → “활성 agent만 업데이트” + 텐서화가 핵심
- 시각화가 시뮬 루프를 막으면 안 됨 → 다운샘플/비동기 메시지/프레임 스킵

## 6. 플랫폼 가정
- 코어 엔진: Python + JAX (CPU/GPU)
- 게임 연동: (1) Python embedding (프로토타입) 또는 (2) C-ABI/FFI로 확장 가능하도록 설계
